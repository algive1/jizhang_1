## 配置与真实联调

1. 在服务端私有环境配置 `INTEGRATION_ENCRYPTION_KEY`，值为 64 位十六进制随机密钥。数据库中的供应商密钥使用 AES-256-GCM 加密；此主密钥需单独备份并跨更新保留，丢失后无法解密。不要提交 `.env`、预览环境、商户私钥或数据库。
2. 微信配置 APP ID、商户号、商户证书序列号、商户私钥、平台公钥及其序列号、32 字节 API v3 密钥、HTTPS 支付/退款通知地址。支付宝配置 APP ID、卖家 ID、应用私钥、支付宝公钥、HTTPS 通知地址。可在支付渠道页面录入，也兼容私有环境和已有 PEM 文件路径。
3. 模型先保存为停用状态，配置 Endpoint、当前供应商支持的模型 ID 和密钥引用，设置服务端 `AI_ENDPOINT_ALLOWLIST` 后再启用。后台连接测试会实际调用指定模型，可能产生费用；指定模型失败不会被备用模型掩盖。费用按供应商返回的 Token 与配置单价估算；未知 usage 或并发中的费用无法作为严格账单上限。
4. 腾讯云填写 Secret ID、Secret Key、识别引擎和可选热词表，再启用 ASR 策略。ASR 默认关闭。APP 使用系统识别或主动选择腾讯云识别；云端使用前显示录音上传授权。仅在请求期间处理音频，不落库；识别文字仅有最多 5 分钟的内存幂等缓存。数据库记录状态、时长等元数据，按诊断保留策略清理。
5. 正式环境关闭 `ALL_FEATURES_FREE_FOR_TESTING`；APP 调试版默认保留测试免费模式，Release 默认关闭。真实会员权限、渠道绑定、支付回调和录音需在正式配置后逐项验收。

腾讯一句话录音限制按 [腾讯官方接口说明](https://cloud.tencent.com/document/product/1093/35646) 实现：最长 60 秒、Base64 数据不超过 3 MB。模型接口依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/)；模型 ID 由后台配置，不固定旧型号。

### 退款和补偿

当前支持全额退款。退款重试保留第一次的退款编号、原因和金额，遵循 [微信退款接口](https://pay.wechatpay.cn/doc/v3/merchant/4013070371) 与 [支付宝退款接口](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/api-list/alipay-trade-refund.html) 的幂等要求。

新订单记录会员发放区间；退款成功只回收该订单尚未使用的时长，并调整之后的续费区间，已用完的旧周期不会扣除后续购买时长。缺少发放记录的历史订单拒绝自动退款，需要人工核查。

`PAYMENT_RECONCILE_ENABLED=true` 可启用每分钟补偿，检查最近 7 天超过 60 秒的待支付订单及待退款记录，每批最多 20 条。APP 回到前台也会刷新待支付订单。此能力是订单状态补偿；T+1 渠道账单与资金差异对账仍需后续开发。

## 后端更新协议

后台负责创建并派发任务；实际拉取镜像、切换服务和回滚由正式服务器上的受控部署执行器完成。当前仓库提供手动执行脚本，尚未配置或执行生产更新。

配置 `BACKEND_IMAGE_REPOSITORY`、HTTPS 的 `BACKEND_DEPLOY_URL` 和至少 32 字符的 `BACKEND_DEPLOY_SECRET`。镜像必须属于指定仓库并固定为 `repository@sha256:摘要`；首次执行前需完成一小时内的后台数据库备份，同一时间只允许一个活动任务。

部署请求为 POST JSON：

```json
{"id":"任务 UUID","version":"1.0.1","image":"仓库@sha256:64位摘要","action":"update","backupId":"备份 UUID","databaseVersion":0}
```

请求头：`Idempotency-Key` 为任务 ID；`X-Deploy-Timestamp` 为 Unix 秒；`X-Deploy-Signature` 为 `HMAC-SHA256(secret, timestamp + "." + 原始 JSON)` 的十六进制结果。执行器应按 ID 幂等受理，并返回 `{"id":"同一任务 UUID","status":"accepted"}`。

执行器向 `/api/v1/system/deployment-result` POST 回执，使用相同的时间戳和签名规则：

```json
{"id":"任务 UUID","image":"任务的完整镜像摘要","status":"succeeded","message":"就绪检查通过"}
```

回执状态允许 `running`、`succeeded`、`failed`；时间戳有效期 5 分钟。草稿、错误签名、错误镜像和覆盖已经结束的任务均被拒绝。执行器还需落实签名校验、仓库限制、持久化幂等状态和可靠回执。

`server/scripts/deploy.sh` 在生产主机手动运行，先备份，再拉取并切换固定摘要镜像，检查就绪；失败恢复旧镜像。脚本不自动恢复数据库，也不自动发送上述回执。上线前需确保迁移兼容性，并演练经审核的数据库恢复流程。

正式部署使用 `server/docker-compose.production.yml`，保留同一 Compose 项目及数据库卷。单独运行 `admin-web/compose.yaml` 时需设置既有后端网络与 API 上游，避免建立第二套业务数据库。
