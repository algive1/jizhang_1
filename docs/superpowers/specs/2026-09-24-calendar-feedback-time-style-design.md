# 消费日历与统一日期时间交互设计

## 目标

修复消费日历滚动内容被底部“本月概览”遮挡的问题；让记账完成后的反馈提示始终位于全局底部导航和“记一笔” FAB 之上并使用主题化视觉；清理旧的 Material 日期选择弹窗，统一日期/时间选择入口的视觉和交互。

## 范围

本次只修改以下三类 UI 行为：

1. 消费日历内部 Scaffold 与滚动正文的布局关系。
2. 记一笔保存成功/部分成功及页面内校验反馈的 SnackBar 样式和位置。
3. 所有业务页面的日期选择入口，以及已有日期+时间入口的统一约定。

不修改账务计算、数据库结构、路由语义、交易保存流程或导航栏/FAB 的视觉几何。

## 设计方案

### 1. 消费日历

消费日历继续使用固定在页面底部的“本月概览”，但内部 Scaffold 不再让正文延伸到 `bottomNavigationBar` 后面。这样滚动列表的可见区域在概览卡片上方结束，选中日期的最后一条流水和“记一笔”入口可以滚动到可见位置，不会被概览卡片绘制层盖住。

验证覆盖 320dp 窄屏、大字号、滚动到最大偏移，以及概览卡片仍可点击/可见。

### 2. 记账反馈

新增一个轻量的应用反馈 SnackBar 构造器，使用当前主题的 surface / onSurface / divider 颜色、圆角和浮动行为。底部间距根据 `AppNavGeometry` 计算：同时避开底部安全区、导航胶囊和中央 FAB，保留少量呼吸空间。记一笔的 `_showMessage`、保存成功和“已入账但后处理失败”路径统一使用该样式。

消息内容和保存时机保持不变；只改变反馈组件的外观和屏幕位置。

### 3. 日期与时间选择

日期+时间选择继续使用记一笔的 `TimeSelector.show`。

纯日期字段统一使用现有 `AppDatePicker.show`，它已经使用项目统一的底部表单、Cupertino 滚轮、主题表面和安全区处理。为该组件增加可选的 `minimumDate` / `maximumDate` 参数并将初始值限制在范围内；删除所有业务页面直接调用 `showDatePicker` 的旧 Material 弹窗，同时保留每个旧入口的日期范围，不改变可选日期业务规则。

本次不引入新的日期选择器依赖，也不把纯日期字段错误改成必须选择时分的日期+时间流程。

## 文件边界

- 修改 `lib/features/calendar/presentation/consumption_calendar_page.dart`：修正内部 Scaffold 的正文/底部概览布局。
- 修改 `lib/core/widgets/app_date_picker.dart`：为统一日期滚轮补充可选的最小/最大日期约束。
- 新增或修改 `lib/core/widgets/app_snack_bar.dart`：集中构造避让全局导航与 FAB 的主题化浮动提示。
- 修改 `lib/features/bookkeeping/presentation/quick_add_sheet.dart`：接入统一反馈提示。
- 修改仍直接使用 `showDatePicker` 的业务页面：替换为带范围参数的 `AppDatePicker.show`，并补齐 import。
- 修改/新增相关 Flutter widget 测试：先验证失败，再验证修复。

不修改第三方库、数据库、资产文件和与本需求无关的既有未提交改动。

## 验收标准

- 消费日历滚动到最大偏移时，最后一条消费记录和“记一笔”入口不被“本月概览”遮挡。
- 320dp 和大字号场景无布局溢出；“本月概览”仍固定可见并可交互。
- 记一笔点击完成后，提示不被导航栏或 FAB 覆盖，提示背景不再是默认黑色，并在四套主题下保持文字可读。
- 记一笔校验失败与部分成功提示也使用同一反馈样式。
- `lib/` 中不再有业务页面直接调用 `showDatePicker`；日期入口统一使用项目组件。
- 既有日期字段的范围、保存值和业务语义不改变。
- 定向测试、范围 `flutter analyze`、相关测试和 `git diff --check` 通过；项目支持时完成 Debug APK 构建。
