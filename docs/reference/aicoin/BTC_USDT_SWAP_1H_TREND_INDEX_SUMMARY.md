## 原始代码的根因问题

原稿先修改 `long_count` / `short_count`，再调用交易函数：

- 开仓条件成立时，状态先从 `0` 改成 `1`，随后 `enter...(... && count == 0)` 变为 false。
- 平仓条件成立时，状态先清零，随后 `exit...(... && count > 0)` 变为 false。

AiCoin 官方说明交易指令按脚本顺序下单，因此该顺序可能导致四类交易调用全部失效。原来的 `plotText` 和 `alertcondition` 还会在条件连续成立时重复标注或报警。

修复方案：

1. 用一个 `position_state` 表示 `-1=持空、0=空仓、1=持多`。
2. 先固定 `enter_*_event` / `exit_*_event`。
3. 交易、绘图和预警共用同一批一次性事件。
4. 交易函数执行后才更新状态。
5. 退出当根默认不反手，下一根仍满足严格条件才入场，避免平仓尚未成交就提交反向开仓。

## 0–100 指数定义

方向分 `D` 的范围为 `[-50, 50]`：

| 因子 | 多头 | 空头 |
| --- | ---: | ---: |
| EMA12/26 排列 | +20 | -20 |
| MACD 同向且柱放大 | +20 | -20 |
| MACD 同向但柱未放大 | +10 | -10 |
| RSI7/21 同向且越过 50 | +10 | -10 |
| 只有 RSI7 越过 50 | +5 | -5 |

确认因子：

```text
volume_factor = 放量 ? 1.00 : 0.75
chop_factor   = RSI7<40 或 RSI7>60 ? 1.00 : 0.50
trend_index   = 50 + D * volume_factor * chop_factor
```

区间解释：

- 0–20：强空
- 20–40：偏空
- 40–60：中性或震荡
- 60–80：偏多
- 80–100：强多

成交量没有方向，因此只调整置信度，不直接增加多头或空头分。EMA 金叉/死叉也没有再次计分，避免与 EMA 排列重复加权。

## 数据和计算口径

- OKX 产品 ID：`BTC-USDT-SWAP`。
- OKX K 线返回顺序为 `[ts,o,h,l,c,vol,volCcy,volCcyQuote,confirm]`，API 默认倒序，复算前已按时间升序。
- 只将 `confirm=1` 用作正式信号；至少使用 300 根 1H K 线预热。
- `vol` 对衍生品是合约张数；`volCcy` 是 BTC 数量；`volCcyQuote` 是 USDT 成交额。单一合约内做量比时必须始终使用同一口径。
- 本实现严格保留用户的 `ma(volume, 20)`，即包含信号当根与前 19 根。改成不含当前柱会改变回测边界。
- EMA 以首个完整窗口 SMA 初始化，之后使用 `2/(n+1)` 递推。
- MACD 柱按 AiCoin 定义为 `2 * (DIF - DEA)`。
- RSI 使用 Wilder/SMMA 口径。

## 未解决风险

- `position_state` 是脚本状态，不是 OKX 真实仓位。拒单、部分成交、人工交易、断线或脚本重启会使两者脱节；实盘必须核对账户仓位。
- `amount=1` 是 1 张合约，不是 1 BTC 或 1 USDT。当前 OKX BTC-USDT-SWAP 合约面值为 0.01 BTC，但启动前仍应在下单配置里复核 `ctVal`、`lotSz` 与最小下单量。
- 当前退出规则只有 EMA 死叉/金叉或 RSI7 穿越 50，没有硬止损、止盈、最大亏损、极端波动保护和日内熔断。因此它是趋势/信号模型，不是完整风控系统。
- RSI7 和 RSI21 都来自 1H，准确名称是“双长度 RSI 共振”，不是多时间周期共振。
- RSI 40–60 只能作为中性动量过滤，不能独立证明市场处于震荡。
- 本地没有 AiCoin PC 编译器，代码已按官方 Script v2 语法静态复核，但仍需在 AiCoin 编辑器中实际保存编译并做专业回测；在此之前属于“代码完成但未实际联调”。
