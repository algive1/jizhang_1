# 两个主题的“我的”与设置整理方案

检查日期：2026-10-06。状态：分析方案，等待确认；未修改业务代码。

**检查范围**

- 好好绿：`lib/features/profile/presentation/profile_page.dart` 中的“我的”及 `_settings`。
- 液态玻璃云雾蓝：`lib/features/profile/presentation/liquid_glass_profile_page.dart` 中的“我的”及 `_showSettings`。
- 核对上述入口关联的会员、全部功能、更多服务、外观、数据备份、安全、通知、自动记账、帮助与账号页面，以判断入口与内容是否一致。
- 本次不扩大到首页、流水、资产、洞察等页面的全面审查，也不进行支付、云服务或全应用架构改造。

依据为当前工作区源码、配置及 2026-10-04 两主题截图。截图仅辅助理解布局，结论以当前源码为准；未重新运行应用或验证生产服务。`PRODUCT.md`、旧开发状态和截图中部分内容可能早于现有实现，不能单独据此认定功能不存在。

**总体判断**

两个主题应使用相同的功能目录、目标页面、用户状态与统计口径，保留不同的视觉呈现。当前两套“我的”并不只是皮肤不同，功能组织和部分行为已经分叉。整理应复用现有业务能力，先统一入口和内容，不重写已有账务逻辑。

## 1. 两个“我的”页与设置的差异

## 3. 建议合并后的入口组织

**“我的”保留四类内容：账号与会员、记账概览、常用功能、设置入口。**

账号与会员显示真实登录和会员状态。记账概览使用统一统计范围。常用功能支持两主题共用选择与排序；“全部功能”承载业务工具。设置承载应用偏好、权限、安全与服务信息。

| 归属 | 主要内容 | 整理方式 |
| --- | --- | --- |
| 账号中心 | 昵称、密码、恢复密钥、登录设备、退出登录、注销 | 保留现有功能；会员中心可作为快捷跳转 |
| 会员中心 | 当前方案、到期时间、真实权益、套餐、订单、恢复购买、会员问题反馈 | 使用共同状态来源；从两主题进入得到相同体验 |
| 全部功能：账本与资产 | 我的账本、共享成员、账户与资产、分类 | 账本管理作为主入口；共享成员权限是当前账本的管理项，独立入口可保留为快捷方式 |
| 全部功能：记账工具 | 自动记账、小票识别、账单导入、周期账单 | 自动记账承担识别来源与授权管理；其他工具保持独立业务流程 |
| 全部功能：规划与账单 | 预算、目标、信用分期、财税与账单 | 从设置移出；预算与目标不用合成一套业务，只统一目录与命名 |
| 设置：外观 | 两款主题、亮色/暗色、金额隐藏偏好 | 统一名称为“外观设置”；顶部切换作为同一设置的快捷操作 |
| 设置：备份与数据 | 云备份、本地备份、恢复、导入、导出 | 统一入口。导入可同时在记账工具保留快捷入口，但使用同一页面 |
| 设置：安全与隐私 | 应用锁、匿名使用统计、权限说明、隐私政策、账号安全快捷入口 | 从备份页抽出设置项；不建立空泛的安全宣传页 |
| 设置：通知与提醒 | 公告/账号/服务推送，现有本地提醒的设置入口 | 与“读取支付通知”的识别权限区分清楚 |
| 设置：帮助与反馈 | 使用问题、提交反馈、我的工单 | 合为帮助中心；去掉更多服务中重复维护的目录 |
| 设置：关于与协议 | 版本、用户协议、隐私政策、会员协议 | 一个协议目录，账号注册/会员购买等场景仍保留必要的协议链接 |

这里的“合并”首先是目录和入口的合并。云备份、本地备份、导入、导出仍需各自清楚的操作、结果和恢复规则；账号安全、设备权限、共享成员权限也应按各自对象展示，不混成一个万能权限开关。

允许有多个有用的快捷入口，但入口名称、目标、状态和动作必须相同，不能每个主题各维护一套。

## 4. 开发说明和不适合用户的内容怎么清理

当前正式源码中未搜索到“开发实现”“隐私白皮书”“安全说明页”这些准确标题；仅历史开发文档出现“安全说明”。如果安装包仍有这些标题，应在开发阶段核对构建来源与版本，不能据当前代码编造它们的位置。以下同类内容已在现有入口相关页面确认。

| 位置 / 当前内容 | 处理 | 面向用户的表达或替代 |
| --- | --- | --- |
| 我的：未开放积分 | 删除入口 | 不提供只有“未上线”弹窗的功能 |
| 玻璃我的：推荐 APP 预留说明、安装/打开外观 | 删除模块及说明 | 真实功能接入前不展示 |
| 会员：两位固定评价及“原型示例评价”弹层 | 删除评价模块 | 替换为真实权益对照和购买常见问题，不创造用户评价 |
| 反馈：“真实提交到服务端工单，不再是静态弹窗” | 重写 | “请描述遇到的问题、操作步骤和发生时间。提交后可在我的工单查看进度。” |
| 数据备份：SQLite、设备随机密钥、数据库结构、正在使用的数据库等 | 简化正文；技术实现移到内部文档 | “完整备份包含本机账本及现有附件，使用备份密码加密。请妥善保存密码。” |
| 帮助：前台/定时任务/连接占用数据库、展示层掩码 | 改为操作说明 | “恢复完成后请关闭并重新打开应用。”“隐藏金额只影响显示，不会修改账单。” |
| 云备份：数据集、通道、基线 revision、owner/user_id | 隐藏技术标识；保留关联账号和覆盖风险 | “将本机数据关联到当前账号。”“另一台设备有更新，请先选择如何处理。” |
| 自动记账检测：schema v、规则来源与内部版本 | 从默认检测结果移出 | 默认只显示可识别应用、缺失权限、服务是否正常；详细版本留在故障诊断 |
| 自动记账诊断日志 | 保留有实际支持用途的入口，降低层级 | 放在自动记账故障排查/帮助中；保留用户主动上传及范围说明 |
| 开发实现、技术白皮书 | 如存在用户入口，移出正式设置目录 | 保留到内部开发文档；确有用户价值的段落改为短问答 |
| 隐私政策、用户协议、会员协议 | 保留，统一术语与入口 | 这是用户查看服务规则和数据处理的渠道，不按技术文档一并删除 |
| 读取通知/无障碍/截图用途，备份覆盖与重启要求 | 保留且写清楚 | 这些内容直接影响授权和数据操作，应放在对应操作附近 |

不能只删除“不支持/尚未开放”说明，同时保留暗示可用的按钮或会员权益。未完成入口应移除或明确不可用；已有能力则保留实际限制及恢复方法。

## 5. 从这些入口能发现的基础体验缺口

| 优先级 | 已确认的问题 | 应完善到什么程度 |
| --- | --- | --- |
| P1 | 同一主题切换改变记账活动统计范围 | 统一当前账本/全部账本口径与标题，切换主题不改变业务含义 |
| P1 | 两主题会员卡信息不一致，玻璃卡未充分表达到期/状态 | 共同显示会员状态、到期、续费；加载失败不能当普通会员渲染 |
| P1 | 会员宣传实时同步、多种导出、专属客服，与实际入口能力不一致 | 目前个人云能力是快照备份恢复；页面改称云备份。当前导出是 CSV，现有支持是反馈工单；按真实能力展示 |
| P1 | “数据与安全”无云备份操作；账号中心“云同步”和“本地数据绑定”进入同一绑定页 | 将现有云操作纳入备份与数据；关联账号与首次备份的步骤用用户语言组织 |
| P1 | 云备份没有用户可见的自动备份开关，首次备份后服务按条件自动执行 | 显示是否自动备份、最近成功时间、失败/暂停原因；新增关闭能力应确认后实现 |
| P1 | 备份恢复需要完全重启；恢复前安全副本没有现成的用户恢复入口 | 给出明确的待恢复、已恢复/失败反馈；设计可恢复的安全副本入口，不能只写“已保留副本” |
| P1 | 自动记账、支付通知识别和权限检测分别提供入口/开关 | 统一到自动记账主入口；展示总状态、识别来源、待确认、目标账本/账户和权限修复；复用现有控制与状态 |
| P1 | 自动记账现已提供智能/完全自动入账，部分关联说明仍说永远待确认 | 根据模式准确说明入账行为；完全自动也受账户、分类、交易完整性检查约束，不能写成所有结果一定入账 |
| P2 | CSV 页写导出全部流水，实际 repository 按当前账本取数据 | 明示当前账本和日期范围；如加入全部账本导出，需额外实现并验证权限与账户映射 |
| P2 | CSV 与完整备份共用 `_status`，反馈放在 CSV 卡内 | 操作结果出现在实际操作区域；备份/恢复不应把状态显示到导出流水区 |
| P2 | 账单导入已有预览、映射、去重、保持余额，但没有发现导入批次管理/撤销入口 | 接入口时显示目标账本；批次记录与安全撤销是后续功能，不能当作已支持 |
| P2 | 玻璃的明暗切换/常用功能定制和绿主题照片入口互有缺失 | 统一功能可达性，不要求相同布局 |
| P2 | “安全与隐私”承诺账号安全，实际落在备份导出页 | 分清账号安全、应用锁与隐私设置；账号密码/设备管理复用账号中心现有实现 |
| P2 | 同一功能名称不一致：主题中心/主题外观/个性化设置，数据安全/数据与安全/安全与隐私 | 建立一份短功能清单，两个主题、设置、全部功能共用名称与目标 |

云备份当前最多每 6 小时在应用启动/恢复等条件下尝试一次，不是持续后台实时同步。当前具备冲突检查和整包恢复，不能因为文案不准确就认定“云备份不存在”。本地备份已有密码加密、附件打包、文件校验和暂存恢复，也不需要从零重做。账号中心已有昵称、密码、恢复密钥、设备和注销管理，应整理入口而非重复开发。

## 6. 推荐实施顺序与关联范围

1. **第一批：两个我的与设置目录统一。** 移除积分和推荐 APP 等无实际用途内容；两主题共用菜单、快捷功能配置、命名与会员/统计状态；工具从设置搬到全部功能，设置改为一致的目录。
2. **第二批：关联说明清理。** 处理会员示例评价和错误宣传，改写帮助、反馈、备份和授权说明；保留协议、授权范围与数据覆盖后果；技术诊断放入低频支持入口。
3. **第三批：补全必要体验。** 云备份统一入口和状态/开关，备份反馈与恢复结果，自动记账识别来源/权限入口统一，导出范围说明。涉及新业务能力的批次撤销、安全副本恢复等单列实现。

预计涉及：`profile_page.dart`、`liquid_glass_profile_page.dart`、`profile_cards.dart`、`profile_quick_actions_page.dart`、`profile_services_page.dart`、`profile_quick_actions_controller.dart`、`app_router.dart`；按实际清理范围关联 `theme_settings_page.dart`、会员页面及 catalog、`account_center_page.dart`、`dataset_binding_page.dart`、`data_export_page.dart`、通知与自动记账权限页、帮助/反馈/关于和协议。

不默认改动现有账务计算、共享同步协议或支付后端。减少重复定义即可，不为菜单统一引入大框架。

**确认后开发的验收标准**

- 同一个用户、同一个账本切换两主题，会员状态、统计含义、功能可达性和设置目录保持一致。
- 同名入口打开同一个功能；常用功能选择和排序跨主题保留。
- 积分、推荐 APP 和示例评价等预留内容不再出现在正式页面。
- 设置默认内容不出现 schema、owner/user_id、内部调试标识或开发过程说明。
- 云备份、本地完整备份、CSV 导出分别说明范围并在本操作处显示结果。
- 通知推送与支付通知读取具有清楚的用途和独立状态；关闭操作准确对应目标能力。
- 隐私政策、协议、授权范围、恢复覆盖风险和重启要求仍可访问。
- 对两个主题的登录/游客、有效/到期会员、明暗模式及加载失败状态进行有针对性的验证。

按用户提供的 AGENTS.md“理解-搜索-分析-后输出理解结果。用户确认后再开发”，本次在此停止业务修改，先确认整理范围和方案。
