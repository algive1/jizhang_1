# 页面性能与开关修复（2026-10-05）

本轮按用户“全部修复”的授权实施。修复背景重新缩放、明暗切换重建页面状态、开关等待及保存竞争、返回刷新遗漏、重复查询和重复计算。保留已有图片和玻璃外观。此前的研究见 [源码研究](2026-10-04_研究-页面性能-report.md) 和 [真机研究](2026-10-04_真机-页面性能-report.md)。

## 已修复的行为

| 问题 | 改动与验证 |
| --- | --- |
| 从“我的”进入二级页时背景放大 | 公共 Navigator 不再根据当前路径改变底部留白；四个主路由和会员路由各自持有视口留白。真机进入自动记账、分类、会员时，退出中的个人背景高度均保持 890.29，消除原来 890.29 → 914.29 的变化。自动记账实际入口及边缘滑动返回再次验证。 |
| 明暗切换后滚动、页面选择丢失 | 根应用和普通页面过渡原先分别切换不同类型的背景容器，会替换其内部导航/页面树。改为稳定的容器结构，只更新背景；个人列表另加稳定的 PageStorageKey。真机切暗前后滚动位置均为 43.71；测试还验证导航 State 和财务中心已选标签不被重建。 |
| 自动记账开关感觉无响应 | 在原生调用前先绘制保存状态，开关显示进度；保存确认和服务连接检测分开。原生保存完成后可继续关闭开关，健康轮询至多等待三次 350ms，旧轮询不覆盖新操作。状态读取临时失败时仍保留原生已确认的开关值。真机通过实际触摸关闭、开启，UI 与原生最终状态一致。 |
| 快速切换设置时旧保存覆盖新选择 | 主题、明暗、自动记账策略和常用功能共用简短的乐观保存队列：立即显示选择，顺序落盘，重复值不重复写入；只有最后一个请求失败才回退到最后成功保存值，并给出错误提示。延迟和失败注入测试通过。 |
| 自动记账反复刷新与重复检测 | 丢弃过期运行状态读取；服务健康轮询不再反复刷新待确认列表；检测入口增加重复打开保护。应用恢复和下拉刷新仍更新状态。 |
| 支付通知开关与刷新 | 增加保存反馈和点击保护，读取状态失败有反馈，旧刷新结果不覆盖新状态；保存确认后不必等待连接轮询结束才能再操作。 |
| 通知设置登录返回仍显示旧状态 | 等待登录页面返回再刷新，增加应用恢复刷新和操作去重。真实账号登录流程未在本轮输入凭据验证。 |
| 通知目的地账户重复查询 | 改为按目标账本订阅已有账户 DAO 的流，避免每次 build 创建新的账户查询。 |
| 财务中心主题重建产生重复查询/闪动 | 查询 Future 由 provider 缓存，保存后失效刷新，刷新时保留已有内容。测试验证主题重建和标签往返不会重复查询。 |
| 资产历史重复计算 | 按账户、流水、排除项、币种和日期缓存历史，隐藏金额或切换展示天数时复用结果，真实数据更新仍重算。 |
| 首页恢复重复统计刷新 | 保留跨日刷新；移除无条件恢复刷新，由已有数据订阅和根应用原生记账修订检查处理实际变化。 |

自动记账背景增加显示尺寸解码和静态重绘边界，机器人按展示宽度解码；列表内互不重叠的玻璃卡片共享模糊输入，覆盖列表的底部检测按钮保留独立滤镜。首页互不重叠的同类卡片也共享输入。未关闭玻璃效果，也未改变预算页和自动记账页已有的局部素材风格。

## 真机结果与限制

设备、账本和采样动作沿用研究基线：23116PN5BC、Android 16、1080×2400 输出、Flutter profile / Impeller、约 60Hz。滚动为 8 次往返，过渡为 4 次 push/pop。最终版本数据使用 `final-` 前缀；`fixed-` 为中间版本的探索性复测。

| 最终版本场景 | 帧数 | UI P95 | Raster P95 | 超预算比例 |
| --- | ---: | ---: | ---: | ---: |
| “我的”浅色滚动 | 100 | 1.79ms | 23.43ms | 34.00% |
| “我的”暗色滚动 | 100 | 1.96ms | 21.31ms | 52.00% |
| 自动记账浅色滚动 | 771 | 2.23ms | 16.62ms | 4.15% |
| 自动记账暗色滚动 | 792 | 2.41ms | 16.79ms | 6.94% |
| 首页暗色滚动 | 882 | 1.49ms | 17.18ms | 33.22% |
| 会员浅色滚动 | 784 | 1.32ms | 5.74ms | 0% |
| 资产浅色滚动 | 785 | 1.05ms | 7.84ms | 0% |
| “我的” ↔ 自动记账，浅色 | 229 | 7.97ms | 28.36ms | 23.58% |
| “我的” ↔ 会员，浅色 | 249 | 5.47ms | 20.94ms | 8.43% |

基线自动记账浅色滚动超预算约 14.57%，本轮约 4.15%；其进入/返回过渡 raster P95 从约 42.28ms 降至 28.36ms，中间版本复测为 26.53ms。会员和资产滚动继续保持本轮无超预算帧。

**不能宣称所有渲染卡顿都消失。** 首页与个人中心仍有超预算帧，个人中心暗色的单轮 P95 还高于研究基线，未证明该页面滚动已稳定提速。个人中心滚动距离很短，仅约 100 帧；设备温度、缓存、取样顺序和使用中的数据会影响结果。超预算帧指 UI/raster 任一超过约 16.67ms，不等于实际掉帧数或 FPS。上述表保留未改善结果，不能仅凭自动记账收益推断所有页面的收益。

真实触摸验证使用 ADB 输入，最终读取 UI 与原生状态：关闭为 enabled=false / healthy=false，开启为 enabled=true / healthy=true，busy 均解除。观察日志遍历组件树，不能拿事件时间当作无干扰的物理触摸延迟。延迟桥接测试证明，原生保存等待期间已有可见反馈，旧连接检查不会锁住后续关闭操作。

进入自动记账的实际入口、交互式边缘返回、切换到桌面再恢复已验证；恢复前后个人滚动位置均为 43.71。一次触摸尝试因页面没有处于可采样状态，没有得到按钮坐标，未发生有效点击；对应无 `verified` 后缀的物理点击/返回/恢复日志排除，以带 `verified` 的记录为准。
