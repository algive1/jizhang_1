# 美团微信支付去重及确认保存修复

日期：2026-10-01。

## 修复行为

- 根据美团/美团外卖 → 微信支付成功 → 返回美团的前台切换，记录短期付款会话。金额相同、支付方式或成功页符合本次链路时，微信与美团观察共用会话标识；不同的商户名称、平台订单号不再造成第二次确认。
- 会话仅关联本次链路中的支出；不同金额、已过期链路、旧交易时间、其他应用中断、下一次付款和不同美团订单均不自动合并。没有链路证据时继续保留独立候选。
- 保存后的通知队列补处理不阻塞关闭确认页。账户偏好、附件和分类增强共用 5 秒等待上限；这些步骤超时报告已提交的流水，而不把已入账结果当成未保存。
- 对截图、学习、待确认清理及宿主关闭增加等待上限。关闭或保存反馈回调不返回时，不阻塞已提交的记账结果。
- 确认按钮的完成回调结束后，清除转圈；成功但宿主尚未关闭时显示“已保存”并禁用再次完成。保存前核对稳定流水 ID，已有记录时复用，避免再次扣减余额。
- 保存超时不会撤销已提交的数据；收件箱根据稳定流水 ID 核对并清理已记录候选。附件超时期间保留可能仍在写入的截图文件。

- Android：109 项单元测试通过；新增会话关联与不应合并场景。
- 相关 Dart 静态分析通过。
- ARM64 Release 版本 1.0.0（2011）编译成功，已覆盖安装到连接的小米手机，启动正常，保留应用数据。

本次读取了连接手机的进程日志。手机 Release 包不保留完整 Dart 保存阶段详情，因此没有足够日志证明用户这次卡住的唯一等待点；已复现并修复保存链路中可造成持续等待的路径。尚未代用户发起真实付款。

## 真机复测

1. 美团外卖下单 → 微信支付 → 点击微信完成 → 在记账浮层完成或取消 → 返回美团：同一笔只保留一次确认或一次待确认记录。
2. 已保存后返回美团：不会再次生成同一笔待确认付款；流水和账户余额只变化一次。
3. 再下一笔同金额订单：正常识别为新付款；查看不同旧订单不会被合并。
4. 点击浮层完成：保存后不持续转圈；后续附加处理异常时仍可以从流水查看已提交记录。

付款会话当前覆盖美团及美团外卖的微信支付链路，使用 2 分钟关联窗口；窗口之外缺少共同订单身份的观察仍保留独立候选，避免猜测合并。
