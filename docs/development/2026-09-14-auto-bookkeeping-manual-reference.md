# 自动记账产品手册参考

日期：2026-09-14

## 结论

钱迹的官方文档更偏“工程化使用手册”：明确说明 Android 自动记账依赖无障碍服务、通知权限和悬浮窗权限，并把后台保活、电池优化、支付保护、日志和失败场景写清楚。一木的官方文档更偏“功能说明 + 设备适配教程”：强调支付完成或打开账单详情后弹出新增账单窗口，同时明确说明自动记账受系统保活和第三方 App 页面变化影响，不能承诺所有设备长期稳定。

## 钱迹值得参考的内容

1. **开启前置条件清晰**：无障碍用于读取支付页面，通知用于后台运行和展示服务状态，悬浮窗用于在其他 App 上层显示确认窗口；同时建议忽略电池优化。见[钱迹 Android 自动记账用户指南](https://docs.qianjiapp.com/auto/qianji_auto_android.html)。
2. **对稳定性边界说得很实在**：第三方 App、Android 系统和无障碍服务都会影响触发，支付后不一定每次都能弹窗。钱迹还专门说明微信/云闪付可能需要退出支付页，或关闭系统支付保护。见[钱迹 Android 自动记账用户指南](https://docs.qianjiapp.com/auto/qianji_auto_android.html)。
3. **有可见的运行日志**：自动记账页提供“查看日志”，可以看到识别过程、AI 匹配结果和配额使用情况。见[钱迹自动记账 AI 用户指南](https://docs.qianjiapp.com/auto/qianji_auto_ai.html)。
4. **AI 不应阻塞主流程**：AI 匹配失败、网络异常或超过 3 秒时自动回退到本地逻辑，不能因为 AI 不可用而阻塞记账。见[钱迹自动记账 AI 用户指南](https://docs.qianjiapp.com/auto/qianji_auto_ai.html)。
5. **高级修复应当谨慎**：钱迹提供通过 ADB 授予 `WRITE_SECURE_SETTINGS`、帮助恢复被系统关闭的无障碍服务，但这是高级能力，必须说明用途、风险和撤销方式。见[钱迹自动记账助手说明](https://docs.qianjiapp.com/auto/adb_grant/qianji_auto_assistant.html)。

## 一木值得参考的内容

1. **用户感知简单**：官方产品页把自动记账表达为“常见支付场景自动触发记账，一键记录”，并将自动、语音、文字、截图几种入口并列展示。见[一木官方产品页](https://www.yimuapp.com/index.html)。
2. **Android 手册明确弹窗时机**：消费完成的一瞬间或进入历史账单详情时弹出新增账单窗口，首次识别后允许用户设置分类、账本和标签，后续可以自动填充。见[一木 Android 自动记账手册](https://www.yimuapp.com/doc/bill/auto.html)。
3. **权限和保活说明完整**：一木同样要求无障碍、通知栏和悬浮窗权限；通知栏不是绝对必需，但建议开启以提高稳定性并展示运行状态；不同厂商还需要自启动、后台运行和电池优化设置。见[一木 Android 自动记账手册](https://www.yimuapp.com/doc/bill/auto.html)及[Vivo 保活设置](https://www.yimuapp.com/doc/auto/autoVivo.html)。
4. **隐私承诺需要放在用户能看到的位置**：一木说明自动记账通过无障碍获取指定 App 的屏幕文字，用于筛选账单，不做其他存储；其隐私手册还说明默认记账数据保存在本地。见[一木隐私政策](https://www.yimuapp.com/doc/privacyPolicy.html)。
5. **重复账单要有明确口径**：一木将金额相同且账单时间相差一分钟以内作为重复判断参考，但仍提示用户确认；这适合我们继续保留“候选交易去重 + 用户确认”的双保险。见[一木 Android 自动记账手册](https://www.yimuapp.com/doc/bill/auto.html)。

## 对当前项目的落地建议

### 近期必须保持

- 采用“识别到候选交易 → 弹出确认页 → 用户点击完成后才入账”，不要直接静默写入。
- 继续保留常驻通知，并在通知中展示“运行中 / 等待无障碍 / 权限不足 / 最近一次识别时间”等状态。
- 通知点击进入自动记账设置页；在通知或设置页提供关闭自动记账的明确入口。
- 日志只记录阶段、页面类型、候选结果、去重结果、弹窗结果和失败原因，不记录完整金额、商户、页面树或截图，避免大量磁盘写入和敏感信息泄漏。
- 对“服务正常但页面树为空”“未匹配成功页面”“支付保护阻止弹窗”“悬浮窗不可用”“重复交易已忽略”分别给出可理解的原因。

### 下一阶段适合补齐

- 自动记账设置页增加权限检查清单：无障碍、通知、悬浮窗、自启动、电池优化；每项显示当前状态和跳转按钮。
- 增加“支持的应用与场景”页面，区分“已适配”“需要退出支付页”“仅支持账单详情”“暂不保证”。
- 增加“运行日志”复制/导出功能，导出前自动脱敏，便于反馈问题。
- 后续如接入 OCR/AI，坚持本地解析优先、AI 超时回退本地逻辑，并明确截图或文本是否会离开设备。
- 关于、反馈建议、使用手册放入个人中心，自动记账手册应包含权限、保活、通知栏、重复判定和支付保护排查。

### 暂不建议立即做

不要马上加入 ADB 高级修复或 `WRITE_SECURE_SETTINGS`。当前首先应把“权限状态可见、通知状态可见、日志可诊断、支付场景不误弹/不重复弹”做稳定；高级修复需要单独的安全说明、授权流程和撤销入口。

## 当前实现对照

已具备：确认弹窗独立流程、常驻前台通知、候选交易去重、应用内运行日志、微信页面识别修正，以及遍历可见无障碍窗口的最新兼容修正。

仍需真机重新扫码支付验证最新 APK。此前日志已确认问题从“支付页面未被识别”推进到“支付页面已识别但当前无障碍根节点为空”，最新版本已增加可见窗口遍历和短时重试；在用户再次支付前，不能宣称扫码弹窗已经完全修复。
