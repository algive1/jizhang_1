# 多平台自动记账能力评估

日期：2026-09-14

## 结论

支付宝、微信、云闪付以及电商/生活服务平台的自动记账整体可行，但需要按应用包名、页面 Activity、场景和版本建立识别适配器。不能只用一套通用规则覆盖所有页面。

推荐的第一版链路是：无障碍页面文字读取优先，识别不到时再使用本地 OCR；规则无法确定时才交给 AI 结构化，并始终进入无键盘确认页，由用户点击完成后保存。

## 当前代码能力

- 自动记账原生链路目前只接入微信包名 `com.tencent.mm`，且只解析微信支付成功/账单类页面的无障碍节点。
- 现有支付通知监听支持微信、支付宝、云闪付的通知文本，但处理后会直接走自动保存，不是“弹出确认页”模式。
- 目前没有截图采集实现，也没有 OCR SDK 或 OCR 服务实现。`TransactionSource.ocr` 只是数据枚举。
- 代码有 `AiParsingGateway`、JSON 解码器和混合解析器接口，但没有接入具体 AI Gateway；当前“AI 记账”入口实际仍以本地规则解析为主，也不支持图片输入。
- 当前悬浮卡片只展示识别结果并提供关闭按钮，还没有打开 Flutter 无键盘确认页的完整交互。

## 目标功能的关键边界

1. 扫码付款、付款码付款页面本身通常只能证明用户正在发起支付，不能证明支付成功。默认应在成功页或账单详情页触发，避免未完成支付也生成流水。
2. 转账、红包需要区分发出和收到；发出一般记支出，收到一般记收入，不能统一按支出处理。
3. 打开历史账单详情也可能触发识别，必须优先使用订单号/交易号去重，金额和商户只能作为兜底去重条件。
4. 自定义绘制、WebView 或无障碍树不暴露文本的页面，需要截图/OCR；截图权限、后台运行和隐私说明需要单独处理。
5. 京东、淘宝、拼多多、美团等应用需要提供实际支付成功页或订单详情页样本，因为同一平台不同版本、不同支付渠道的字段位置可能不同。

## 需要提供的材料

最省事的方式不是先整理大量截图，而是在真机上逐个执行场景，我读取包名、Activity、无障碍树和必要的脱敏截图。每个场景至少需要：

- 支付成功页或账单详情页：金额、商户、时间、订单号分别在哪里。
- 场景语义：支出、收入、退款、转账发出、转账收款、红包发出或红包收款。
- 是否允许读取账单历史页，是否需要只识别当前刚完成的支付。
- 账户映射规则：支付宝/微信/云闪付/银行卡分别对应哪个账户；不同尾号是否需要区分。
- AI/OCR 方案选择：优先本地 OCR，还是允许将脱敏后的 OCR 文本/截图发送到已有后端。若使用云端，需要提供接口协议、鉴权方式和返回 JSON Schema，不应把密钥硬编码进 APK。

## 建议实施顺序

1. 先完成微信、支付宝、云闪付的成功页/账单详情页无障碍适配，并统一为待确认状态。
2. 增加无键盘 Flutter 确认页，复用现有账本、账户、分类和去重服务。
3. 接入本地 OCR 作为无障碍读取失败时的兜底，并保存识别来源和置信度。
4. 再扩展京东金融、京东、淘宝、拼多多、美团/淘宝闪购等页面规则。
5. 最后接入可选 AI fallback，只处理 OCR/无障碍抽取后的文本或明确授权的截图，不让 AI 直接无确认写账。
