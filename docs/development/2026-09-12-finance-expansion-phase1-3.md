# 好好记账功能扩展阶段记录（2026-09-12）

本窗口在完成现有架构审计后，继续执行了统一交易模型、报销、消费日历、周期账单、分期基础、账户详情、退款和搜索几个垂直切片。

逐项完成审计见：[2026-09-12-finance-expansion-completion-audit.md](2026-09-12-finance-expansion-completion-audit.md)。

## 已完成

- `transactions` schema 从 12 升到 15，新增 `related_transaction_id`、报销状态/金额/日期/备注、退款状态/金额，以及独立的 `recurring_bills`、`installment_plans` 表。
- 旧数据库迁移采用 forward-only additive migration；schema 13 字段增加了列存在性检查，兼容测试中“数据库已经有列但 user_version 较旧”的情况。
- `TransactionRecord` 增加 `ReimbursementStatus`、`RefundStatus`、关联流水和金额字段；`QuickBookkeepingRequest` 与 Drift repository、共享服务端契约同步支持这些字段。
- `repayment` 仍然减少账户现金余额，但从 `isExpense` 消费统计中分离；部分退款通过 `netExpenseAmount` 进入预算、首页和分析的消费统计。
- 快速记账附件限制为每笔最多 4 个，并显示缩略图；支持替换、删除和长按拖动排序，独立附件表和旧 metadata 迁移能力保持不变。保存过程展示进行中状态，失败项保留原文件选择并可重试；存在失败附件时阻止提交，避免静默丢附件。
- 新增 `/transactions/reimbursements` 报销管理页：待报销/已报销汇总、筛选、统一交易详情、选择到账账户并创建带 `relatedTransactionId` 的回款流水。
- 新增 `/transactions/calendar` 消费日历页：按真实交易计算月历、日金额、本月支出、消费天数和最高消费日，支持月份与前后有记录月份跳转。
- 新增 `/profile/recurring-bills` 周期账单页和本地 repository，支持周期类型、周期频率、自动记账、提醒、暂停/恢复、结束、账户/分类和幂等的到期记账。
- 应用启动和回到前台时会执行 `auto_record` 周期账单补齐；每个到期日使用稳定流水 ID 幂等，失败会在周期账单页显示可关闭提示。
- 新增分期计划模型、repository、`/profile/installments` 管理页和分期详情页；分期计划必须关联同账本的原始消费，保存总金额、期数、每期本金/手续费、信用卡账户、还款账户、剩余本金等数据。登记还款会双边更新账户，最后一期自动完成，且还款流水不会再次计入消费；分期页可按还款日批量执行到期期数，流水按计划和期数幂等。
- 会员购买 bookkeeping 支持 `autoRenew` / `isPermanent`：自动续费月/季/年商品生成确定性周期账单；一次性和永久会员只生成一次性消费；支付侧确认取消自动续费时可通过本地 hook 结束对应周期项。
- 资产总览中的账户卡片进入 `/profile/accounts/:accountId`，展示余额、本月流入/流出和全部/收入/支出/转账/调整流水筛选。
- 交易操作菜单新增退款登记：退款回款创建 `refund` 交易并关联原消费，原消费累计退款金额驱动 `partial/refunded` 状态和净消费统计；回款和原流水状态在同一数据库事务中提交。退款回款支持编辑和撤销，撤销会恢复原消费状态并冲回回款账户。
- 全局搜索增加金额比较（如 `500元以上`）、日期、账户、标签 metadata、报销状态和周期账单匹配。
- 账本抽屉的长按管理补齐了账本排序和默认账本偏好；顺序与默认值写入本地设置，启动恢复默认账本。
- 通用流水软删除补齐当前账本作用域与关联保护；仍有退款、报销、分期计划或分期还款引用时会明确阻止删除，避免孤立关联；共享 ID 映射补齐关联流水和分期账户引用。

## 视觉素材决策

新增页面复用首页现有的暖米白、鼠尾草绿、圆角卡片、`AppCard`、`MoneyText` 和状态标签，没有引入 CSS 模拟复杂插画。当前功能可以在没有新图片素材的情况下保持一致 UI；若后续需要增强场景氛围，建议由 ImageGen 统一生成以下低透明度插画：消费日历（393×220，右上安全区）、报销票据（320×180，右侧安全区）、周期账单循环日历（320×180，右上安全区）和资产钱包（360×200，左侧安全区），正文和金额区域保持纯色留白。
