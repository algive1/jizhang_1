# 广告 Placement 接入前置清单（2026-09-19）

当前阶段只完成广告规则、远程 Placement 配置与 Provider 边界，不代表第三方广告 SDK 已可直接上线。

## 已完成

- Placement 与业务页面解耦。
- Free / Pro / Family 与 ad_free 权益过滤。
- 第三方广告对 Pro / Family 额外 fail-closed，即使 entitlement 异常也不展示。
- 支付、登录安全、账单编辑、数据恢复等受保护路径禁止广告。
- 开屏广告新设备前 24 小时禁止展示。
- 开屏每天最多 1 次，客户端与服务端双重限制。
- 安装时间使用设备本地 Application Support 标记，不进入 SQLite，不跟随好好记账本地备份/云恢复到新设备。
- App 启动即提前创建安装标记，避免未来接广告时把老用户全部当成新安装。
- 远程 Placement 配置有严格 schema；配置异常时 fail-closed。
- 配置服务不可用时使用最近一次内存有效配置；冷启动失败时回退内置内部推广位。
- 未设置 SHARED_API_BASE_URL 时不发起广告远程配置网络请求。
- 第三方 Provider ID 必须与当前 AdProvider 匹配且 Provider 可用。
- 第三方 Native 广告不会被普通 AppCard 伪渲染。

## 真实广告 SDK 上线前仍必须完成

1. 选定广告供应商并实现独立 AdProvider Adapter，不允许页面直接引用供应商 SDK。
2. 在初始化第三方广告 SDK 之前完成应用级隐私同意流程和对应 SDK 隐私披露；没有有效同意时 Provider 必须保持 unavailable。
3. Native 广告必须使用供应商要求的官方 Native View/Renderer，由 SDK 负责曝光、点击和广告标识；禁止把第三方素材复制进普通业务卡片。
4. Rewarded 广告必须增加服务端奖励兑换接口。客户端“播放完成”只能产生待验证凭据，不能直接修改 AI 次数或会员权益。
5. Rewarded 服务端需要幂等 rewardId/providerReference，并限制单用户/设备/日领取次数。
6. 开屏广告真正启用时需要加入统一 Startup Coordinator，顺序至少为：
   - 本地启动海报
   - 版本更新检查
   - 若存在强制更新：不展示广告
   - 若展示过可选更新弹窗：本次启动跳过广告
   - 否则再评估 Splash Placement
   不能让更新弹窗和开屏广告同时竞争顶层 UI。
7. 第三方广告失败、超时、无填充、SDK 初始化失败时必须直接进入 App，不能卡启动。
8. 第三方广告曝光/点击/关闭的应用侧事件与广告供应商统计需要分开记录；供应商收入与归因以供应商后台为准。
9. 广告配置与 SDK 密钥分离：Placement JSON 可以远程配置，SDK App ID/密钥不得通过公开 Placement API 下发。
10. 正式发布前需要真机验证 Android/iOS：冷启动、热启动、后台恢复、无网络、弱网、会员切换、退出登录、新设备恢复备份、强制更新与广告互斥。
11. 首页/个人中心现有会员卡是产品 UI，不强行改造成第三方广告位。当前真正使用 PlacementSlot 的页面应逐页评估后再扩展，避免重复推广和信息密度失控。

## 明确禁止

- 不允许第三方广告出现在快速记账、账单编辑、账单确认、目标完成、数据恢复、支付、登录和安全流程。
- 不允许高风险贷款、博彩、不可信投资类内容进入远程配置。
- 不允许为了提高填充率绕过 Pro / Family 免广告。
- 不允许把客户端 RewardGrant 当成服务端权益凭证。
- 不允许在未配置真实 SDK 时用假广告卡片模拟“已经接入”。
