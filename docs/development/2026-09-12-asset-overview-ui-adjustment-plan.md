# 资产总览页面 UI 适配计划（2026-09-12）

## 1. 当前问题与根因

本次只针对 `/profile/assets` 的移动端布局与交互适配，不改变资产汇总、账本隔离、流水查询、账户管理和金额隐私逻辑。

### 1.1 卡片标题、页面边距和近期记录密度

- 资产页 `ListView` 当前左右边距为 `12dp`，首页主体左右边距为 `16dp`，导致两个页面的内容基线不一致。
- `AssetSectionHeading` 及图表卡标题使用 `13sp`，明显小于首页同类区块标题的 `16sp`；快捷入口和近期变动行的文字也偏小。
- `_RecentRow` 使用 `10sp` 标题/副标题、`30dp` 图标，行间没有分隔和足够的上下留白；首页的 `TransactionTile` 使用更大的主标题、较清晰的元信息和固定行内节奏，因此两者观感不一致。

### 1.2 资产变化趋势不可正常横向查看

- `AssetTrend` 直接让 `CustomPaint` 使用卡片剩余宽度绘制全部采样点。
- 30 天按日采样、1 年按周采样都被压缩到约半张卡片中；没有 `SingleChildScrollView`，用户无法横向查看被压缩的趋势细节。
- 趋势卡本身仍应保持双列布局和现有卡片高度，横向滚动只发生在趋势绘图区内部，避免页面整体布局被撑宽。

### 1.3 详情弹窗高度和信息完整度

- `_AssetSheetFrame` 目前固定 `heightFactor: .84`，在手机上接近全屏，超过用户期望的半屏级详情面板。
- 资产分布详情只有环图和账户列表；资产变化详情只有变化金额、百分比和趋势图，缺少对当前数据的简短解释。
- 弹窗应采用“内容不足时按内容收缩、内容较长时在面板内部滚动”的策略，避免固定高度产生大片空白，同时保留小字号/大字号和小屏可读性。

### 1.4 右上角“全部账本”

- 该按钮和 PopupMenu 完全由资产页 `_Header` 自己实现，不是全局账本抽屉或首页账本切换依赖。
- 资产页默认通过 `assetDashboardAccountsProvider` 汇总可见账本的资产；移除按钮后保留默认汇总口径，删除仅限页面顶部的入口和其无用筛选状态，不改其他页面的账本能力。

## 2. 实施方案

按小步切片实现，每个切片都保持可编译并运行相关测试。

### 切片 A：统一页面边距和卡片层级

涉及：

- `lib/features/accounts/presentation/asset_overview_page.dart`
- `lib/features/accounts/presentation/asset_dashboard_cards.dart`

改动：

1. 将资产页主体左右边距调整为与首页一致的 `16dp`，只调整外层内容基线，不改变区块顺序、双列图表和账户四列结构。
2. 将区块标题提升到接近首页的可读字号（目标 `15–16sp`），并同步调整标题右侧操作文字；趋势卡会保留更紧凑的标题/周期控件适配，避免窄卡片换行破坏原布局。
3. 适度提升快捷入口和账户/近期记录的标题与元信息字号，维持原有暖米白、植物绿、圆角和阴影，不新增视觉风格。

验证：

- `flutter analyze` 相关 accounts 文件。
- 320/393/430dp、1.0/1.6 字号的资产页面布局测试，无 `RenderFlex overflow`。

### 切片 B：让近期资产变动与首页交易行使用同一阅读节奏

涉及：

- `lib/features/accounts/presentation/asset_overview_page.dart`

改动：

1. 保留资产变动当前按账户影响计算金额的真实业务逻辑，不能直接把转账金额替换成流水原始金额。
2. 调整 `_RecentRow` 的主标题、日期/分类、金额字号和行内上下间距，使其接近首页 `TransactionTile(homeStyle: true)` 的阅读层级。
3. 增加轻量行间分隔/留白和更稳定的金额宽度，避免长商户名或长金额挤压左侧信息。
4. 保留现有筛选项、最多 3 条首屏记录、小贴士关闭状态、查看全部入口和交易详情/操作链路。

验证：

- 补充不同标题长度、收入/支出/转账/资产调整的 widget 断言。
- 检查金额隐藏、320dp 与 1.6 倍字号下仍可滚动且无溢出。

### 切片 C：趋势图内部横向滚动

涉及：

- `lib/features/accounts/presentation/asset_dashboard_charts.dart`
- `test/asset_overview_interaction_test.dart`（必要时补充专门的趋势交互测试）

改动：

1. 将 `AssetTrend` 的趋势绘图区包进水平 `SingleChildScrollView`，只扩大绘图内容宽度，不改变趋势卡的外部宽度和双列布局。
2. 依据采样点数量设置最小绘图宽度：近 7 天可以保持当前紧凑显示；近 30 天和近 1 年为每个采样点保留可读间距。
3. 使用独立 `ScrollController`，周期切换后把视口定位到最新日期一侧，同时允许用户左右拖动查看历史点；趋势图坐标、最新值气泡、语义标签和金额隐私状态保持真实且不变。
4. 处理无数据/未来日期流水/金额隐藏状态，不能因滚动容器引入空白、越界或父级纵向滚动失效。

验证：

- 测试近 7 天、近 30 天、近 1 年切换；确认 30 天/1 年趋势具有可横向滚动范围。
- 确认拖动趋势图不会打开趋势详情弹窗，也不会把资产页横向撑宽。
- 运行资产页面布局、交互和视觉 QA 测试。

### 切片 D：缩短详情弹窗并补充动态分析摘要

涉及：

- `lib/features/accounts/presentation/asset_overview_page.dart`
- `lib/features/accounts/presentation/asset_dashboard_charts.dart`
- `test/asset_overview_interaction_test.dart`（补充弹窗高度/摘要断言）

改动：

1. 将资产详情面板从固定 `84%` 改为“约半屏到六成屏的最大高度”，具体以可用屏高为上限；内容少时自然收缩，内容多时只在面板内部滚动。
2. 保留现有拖拽/关闭语义、底部圆角、暖色背景和安全区处理；详情面板不遮挡全局布局。
3. 在资产分布详情下增加基于真实账户数据的简短总结：账户数量、最大账户及占比、集中/分散提示。无正余额或金额隐藏时显示对应的保守说明，不生成示例金额。
4. 在资产变化详情下增加基于真实历史点的简短总结：所选区间、净变化方向、可比百分比；明确这是账面净资产变化，不把它描述成投资收益。存在未来日期流水时显示“历史趋势暂不可用”的原因。
5. 总结使用与现有卡片一致的浅色提示容器和小图标，文字控制在 1–2 行附近，避免新增大片留白。

验证：

- 打开资产分布和资产变化详情，断言弹窗高度不再固定为 84%，且摘要出现。
- 验证长账户名、多币种分组、无负债、金额隐藏和未来日期流水场景。
- 运行 `flutter analyze`、相关 widget tests 和 Debug APK 构建。

## 3. 完成标准

- 资产页左右内容边距与首页对齐；现有区块顺序、配色、卡片圆角、图表双列和底部内容不被重排。
- 区块标题和近期资产变动在正常字号下具有与首页一致的阅读层级；大字号下无溢出。
- 近 30 天/近 1 年趋势可在趋势卡内左右滑动，最新数据默认可见，父级卡片点击与周期按钮行为不受影响。
- 两类详情弹窗不再固定占用约 84% 屏幕；内容不足不留大块空白，内容超出时内部可滚动。
- 资产分布和资产变化详情都有基于真实数据的简短分析，金额隐藏/无数据/未来流水时不虚构结论。
- 资产页右上角“全部账本”按钮被删除，其他页面账本能力保持不变。
- 相关测试、静态检查和构建结果明确记录到最终开发总结文档。
