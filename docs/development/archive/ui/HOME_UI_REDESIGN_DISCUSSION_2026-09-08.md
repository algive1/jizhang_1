# 首页 UI 重设计讨论记录（2026-09-08）

## 范围

本记录只整理原型图与当前项目的 UI、数据和交互方案，不包含代码实现，也不把原型图中的示例金额、日期或文案当作业务要求。

## 用户意图

- 参考原型图更有活力的首页信息组织方式。
- 原型图顶部已经展示本月支出后，删除中间重复的“本月支出”大卡片。
- 使用现有的“今日可安心花”和目标阶梯进度能力，融合成新的首屏主卡，填补被释放的空间。

## 当前首页现状

当前 `HomePage` 的顺序是：

1. 我的账本 + 头像
2. 今日安心可花
3. 净资产
4. 本月收支
5. 消费洞察
6. 目标阶梯
7. 最近交易

已有可复用能力：

- `dashboardSnapshotProvider` 已计算本月收入、支出、结余和预算日均可用金额，但 `DashboardSnapshot` 目前只向首页暴露安心可花、结余和是否有预算。
- `BudgetOverview` 已提供预算剩余、已使用、剩余天数、日均可用和预算状态。
- `GoalProgressCard` 已提供目标金额、完成百分比、节点阶梯、当前节点和下一节点提示。
- 目标与预算点击路径已经存在：预算进入预算管理，目标进入目标详情。
- 首页最近交易已经共用流水操作入口；重排时应继续保留这个行为。

当前的主要问题不是缺少卡片，而是信息层级偏散：本月收支、净资产、现金流和洞察连续占据首页空间，真正能驱动用户行动的“今天能花多少”和“正在为哪个目标积累”被分开了。

## 原型图的可取部分与不应直接照搬部分

### 可取部分

- 顶部用一张轻量白色汇总卡集中表达月份、收入、支出、月度结余。
- 下面用趋势、分类、最近记录形成“总览 → 解释 → 明细”的阅读路径。
- 颜色更明快，首屏有一个明确的视觉焦点。
- 重要数字优先，卡片标题和辅助说明更短。

### 不建议直接照搬

- 原型图中间的“本月支出 ¥3,260”与顶部支出重复，应删除。
- 原型图的“比上月节省 18%”不能直接复用。当前项目的分析口径需要先保证本月截至当天与上月同期可比，不能直接把完整上月与当前月相比较。
- 原型图的“结余”是静态示例数字；项目当前的 `forecastBalance` 实际是本月收入减支出的月度净现金流，不等于账户余额或净资产。首页应标为“月度结余”，避免语义误导。
- 原型图的高饱和珊瑚色可以作为辅助强调色，但不宜替换当前暖米白 + 鼠尾草绿体系；警告色仍应保留给超预算等风险状态。

## 推荐首页结构

```text
我的账本                                      头像

[ 2026年9月  ▾                              ]
[ 收入       支出       月度结余             ]  轻量月度汇总

[ 今日可安心花                              ]
[ ¥xxx                                     ]
[ 本月预算剩余 ¥xxx · 还剩 xx 天              ]
[ 目标：买车  ¥xxx / ¥xxx   ●━━●━━◉━━◎      ]  组合主卡
[ 下一站：¥xxx                               ]

[ 净资产 / 收支趋势 / 消费洞察 ]              次级信息

最近交易                                      全部
[ 交易列表 ]
```

### 1. 顶部月度汇总卡

新增一张高度较轻的月度汇总卡，展示：

- 当前账期，例如“2026年9月”；暂不引入没有实现月份切换的假控件。
- 本月收入。
- 本月支出。
- 月度结余（收入减支出）。

点击整卡或月份区域可作为后续月份筛选入口，但如果本轮没有实现月份选择，先保持展示，不做看似可操作的控件。

### 2. “安心可花 × 目标阶梯”组合主卡

建议使用纵向两段式，而不是手机窄屏上的左右两栏：

- 上段是“今日可安心花”，保留现有大金额视觉权重。
- 下段是目标的紧凑阶梯条，展示目标名称、当前金额 / 目标金额、3–5 个节点和下一节点提示。
- 两段之间用弱分隔线或色块区分，不再套两张完整卡片。
- 组合卡的整体高度控制在现有安心卡与目标卡叠加高度的约 60%–70%，让位给趋势和最近交易。

主卡内部需要两个独立点击区域：

- 安心可花区域 → 预算管理；未设置预算时显示“设置本月预算”。
- 目标阶梯区域 → 当前目标详情。

不能让整个组合卡只有一个含义不明确的点击行为。

### 3. 后续内容顺序

建议保留现有真实能力，但改变首屏优先级：

- `CashflowSummaryCard` 作为月度汇总的详细入口，避免和顶部汇总重复时再显示三组大数字；更适合后续收缩为趋势/统计入口。
- `AssetSummaryCard` 保留，但放在组合主卡之后或作为较轻的净资产入口，不与“本月结余”混在一起。
- `InsightCard` 只有在样本足够时突出；数据不足时改为“记录更多后查看消费习惯”，不要让空数据占据核心位置。
- 目标不再在组合卡之后重复展示完整 `GoalProgressCard`；完整阶梯只保留在目标页，首页使用紧凑版本。
- 最近交易继续放在首页下部，并保持点击、长按操作。

## 组合卡的状态设计

### 有预算 + 有进行中目标

显示完整组合卡：安心金额为主，目标阶梯为次。预算状态接近上限或超预算时，数字和说明使用现有 warning 语义，不改变目标进度的绿色表达。

### 无预算 + 有目标

安心区域显示“— / 先设置预算”，明确说明“设置本月预算后计算”；目标阶梯仍然可用。点击安心区域进入预算管理，不能把 0 解释为用户今天只能花 0 元。

### 有预算 + 无目标

安心区域扩展到完整宽度，底部显示轻量 CTA：“设一个正在努力的目标”。不要放假的进度条，也不要把目标创建强行阻塞在记账路径上。

### 无预算 + 无目标

组合卡保留两个真实入口：设置预算、创建目标。文案要把“预算”和“目标”区分开，避免用户误以为目标金额会自动从账户扣除。

### 多个目标

第一版可以继续复用当前 Provider 返回的首个进行中目标，避免扩大数据模型范围；但应在方案上定义“首页优先目标”。长期更合理的是允许用户置顶目标，而不是永久按创建时间选择。

## 数据与实现边界（后续开发时）

建议按最小改动拆分：

1. 先扩展首页月度快照，集中提供月份、收入、支出、月度结余，避免在 Widget 内重复筛选交易。
2. 新建一个首页专用的紧凑目标进度表现，复用 `Goal`、节点计算和目标详情跳转；不要改动完整 `GoalProgressCard` 在目标列表和目标详情中的语义。
3. 新建组合卡组件，内部维护预算区域和目标区域两个独立点击区域。
4. 调整 `HomePage` 的展示顺序，去掉首页完整目标卡的重复展示。
5. 最后再调整视觉：使用当前暖米白/鼠尾草绿为底，增加少量薄荷青或青绿色渐变作为主卡强调；插画只做装饰，不遮挡金额、节点和点击区域。

需要联动检查的内容：

- 预算未设置、超预算、剩余天数为 0、预算金额很大时的金额布局。
- 没有目标、目标完成、节点数量较多、目标名称很长时的阶梯布局。
- 小屏、系统大字体、金额带小数和七位数金额。
- 月度汇总的“结余”与资产总览的“净资产”不能混淆。
- 组合卡的两个点击区域、无数据提示和无障碍 label。
- 首页删除完整目标卡后，目标能力仍需从底部导航和主卡进入。

## 暂不建议本轮一起做

- 直接接入原型图中的搜索、通知、AI 识别等未完成能力。
- 为了视觉相似而新增一套图片资源或更换全局颜色。
- 立即实现月份切换、上月对比和趋势图重做；这些会扩大到分析口径与筛选状态。
- 把“目标进度”与真实账户余额转移绑定。当前目标贡献只是进度记录，不会自动移动账户资金，UI 需要继续保持这个事实。

## 建议的下一步

先确认以下三个产品决定，再进入开发：

1. 首页顶部是否正式加入“收入 / 支出 / 月度结余”三项汇总。
2. 组合主卡是否采用“安心可花上段 + 目标阶梯下段”的纵向结构。
3. 首页先展示一个优先目标，还是要同时支持多个目标横向/轮播展示。

推荐默认选择：加入顶部三项汇总；采用纵向组合卡；第一版只展示一个进行中的优先目标。

## 讨论补充：安心可花的真实口径

用户确认：

- 加入顶部月度汇总。
- 组合卡采用纵向结构。
- 首页只展示一个优先目标；目标页单独支持调整排序。

### 当前代码实际支持什么

当前 `SafeToSpendService` 的计算只有：

```text
今日安心可花 = max(0, 本月预算 - 本月已支出) / 本月剩余天数
```

现有能力边界：

- 只支持月度总预算和分类预算。
- 支持从本月预算、已支出、剩余天数计算日均可用。
- 没有周计划、年度计划或当前周期切换。
- `isPlanned` 只是流水属性，尚未进入安心可花计算。
- 目标当前金额、目标日期和目标节点只用于目标进度与预测，没有自动从支出预算中预留。
- 目标贡献只是目标进度记录，不会自动从账户转出资金。

因此当前的“今日安心可花”不能解释为“扣除了未来计划支出和目标储蓄后的真实安全额度”。它是预算日均值，产品文案需要承认这一点，直到计划支出与目标预留真正接入。

### 推荐的产品口径

组合卡应该同时展示“结果”和“依据”，但不要在主视觉区域堆太多大数字：

```text
今日安心可花 ¥xxx
本期可用支出 ¥xxxx · 已用 ¥xxxx
目标预留 ¥xxxx / 月
目标：买车  ¥xxxx / ¥xxxx  · 下一站 ¥xxxx
```

其中：

```text
本期可用支出
= 本期支出计划
  - 已发生支出
  - 已确认的计划支出
  - 已开启的目标预留
```

```text
今日安心可花
= max(0, 本期可用支出) / 本期剩余天数
```

这里的“目标预留”必须由用户明确开启或确认，不能仅因为目标有一个目标日期，就自动从预算里扣除。否则用户可能只是想记录一个目标，并没有承诺每月从日常支出预算中为它存钱，系统却会无声地降低可花金额。

### 组合卡建议的交互

- 主金额仍是“今日安心可花”。
- 主金额下方显示“本期可用支出”，让用户知道日金额的基础。
- 目标区域显示“本月目标预留”，并用阶梯进度表达长期目标。
- 点击“本期可用支出”或“计算依据”进入预算详情，查看预算、已用、计划支出和目标预留的拆分。
- 点击目标区域进入目标详情；目标页负责调整目标顺序、目标日期和目标计划。
- 未开启目标预留时，目标仍显示进度，但卡片明确写“未计入安心可花”；用户可以主动设置。

### 建议的实现顺序

1. 先保留当前月度预算算法，但把显示文案从“完全安心”解释成“按本月预算计算”。
2. 增加目标预留设置：用户明确指定每月或当前周期为目标预留多少。
3. 将“已确认的计划支出”接入计算，区分已发生流水和未来承诺。
4. 再考虑周/月/年的计划周期。第一版建议以月为主，周和日由月度计划派生；年度计划需要明确跨月分配规则后再做。
5. 最后才把组合卡上的“本期可用支出”升级为扣除计划支出和目标预留后的完整口径。

结论：组合卡应该展示“计划总的可用支出”，但它必须是一个可解释的中间结果，而不是额外的大号数字。真正让用户安心的关键不是把目标进度放进卡片，而是让“目标预留是否影响可花金额”成为明确、可查看、可关闭的用户选择。

## 本轮讨论达成共识

### 首页结构决定

- 顶部加入“收入 / 支出 / 月度结余”轻量汇总。
- “安心可花 × 目标”采用纵向组合卡，不采用手机上的左右两栏。
- 首页只优先展示一个进行中的目标。
- 目标页单独负责目标排序；首页读取排序后的第一个优先目标。
- 原型图中的示例日期、金额、同比节省比例只作为视觉参考，不作为真实业务数据。

### “安心可花”的产品定义

当前功能只能计算预算日均剩余额度：

```text
今日安心可花
= max(0, 本月预算 - 本月已支出) / 本月剩余天数
```

它还不能称为完整的“安全可花金额”，因为以下内容尚未进入计算：

- 未来已确定的计划支出。
- 周计划或年度计划。
- 目标储蓄预留。
- 固定账单、周期支出。

真正完整的口径应为：

```text
本期可用支出
= 本期支出计划
  - 已发生支出
  - 已确认的计划支出
  - 已开启的目标预留
```

```text
今日安心可花
= max(0, 本期可用支出) / 本期剩余天数
```

目标预留不能因为用户创建了目标就自动产生。目标可能只是愿望记录，不一定代表用户承诺每月从日常预算中存入固定金额。系统可以按目标金额和目标日期给出建议预留值，但必须由用户确认后才影响安心可花。

### 组合卡最终信息层级

```text
今日安心可花
¥274

本期可用支出 ¥2,740 · 还剩 10 天

预算 ¥8,000 · 已用 ¥3,260 · 计划支出 ¥1,000 · 目标预留 ¥1,000

目标：买车
¥20,000 / ¥50,000
● ━━━ ● ━━━ ◉ ━━━ ◎
下一站 ¥30,000
```

设计原则：

- “今日安心可花”仍然是卡片唯一的主数字。
- “本期可用支出”展示计算依据，但不再做成第二个大号主卡。
- 预算、已用、计划支出、目标预留以小字号或展开详情展示。
- 点击“本期可用支出 / 计算依据”可以查看拆分。
- 点击目标区域进入目标详情。
- 没有开启目标预留时，目标照常显示进度，但明确标记“暂未计入安心可花”。

### 分阶段实现边界

1. 第一阶段：保留月度预算算法，增加用户明确设置的目标预留，并在首页解释计算依据。
2. 第二阶段：接入未来计划支出、固定账单和周期支出。
3. 第三阶段：支持周计划、月计划、年度计划，并明确不同周期之间的分配规则。

第一阶段不应把目标日期、目标预测速度或目标当前金额直接自动当成支出预算扣减项，以免用户没有确认就被降低可花额度。

### 目标排序

首页第一版只展示一个优先目标；目标页需要提供独立排序能力。后续实现时应增加明确的排序字段或置顶状态，不能永久依赖创建时间决定首页目标。目标排序和目标预留设置都属于目标管理能力，不应塞进首页主卡中完成。

### 当前实现风险

在计划支出和目标预留真正接入之前，首页文案不应暗示“已经考虑所有未来责任”。第一阶段可以使用“按本月预算计算”或“本期可用支出”这样的透明说明，避免把当前的预算日均算法包装成完整财务安全判断。

## “值得关注”展示方案

### 功能定位

当前“值得关注”来自消费分析，例如“22:00 后消费 ¥xxx，较上月同期 xxx%”。它是基于用户数据生成的消费洞察，不是系统公告，也不是必须处理的通知。因此不建议使用红点、铃铛或大面积公告卡的表现方式。

它更适合作为首页的“轻量洞察条 / Insight Banner”：让用户知道有一个值得查看的发现，点击后进入分析页；不会抢过安心可花和目标的主视觉。

### 推荐形态

```text
┌──────────────────────────────────────────────┐
│  ◐  值得关注                                  × │
│     22:00 后消费 ¥xxx，较上月同期 +xx%         │
└──────────────────────────────────────────────┘
```

建议规格：

- 放在“安心可花 × 目标”组合主卡之后，现金流、资产等次级信息之前。
- 高度控制在约 64–76dp，不再使用当前完整 `InsightCard` 的大圆形图标和多层标题结构。
- 左侧保留一个小型图标或彩色圆点，中间最多两行文案，右上角放 18–20dp 的关闭按钮。
- 整条内容（关闭按钮除外）可点击，进入分析页对应的消费时间分布或洞察详情。
- 不需要同时放箭头和关闭按钮；整条可点击已经足够表达“可查看”，右上角只保留一个小 `×`，减少操作元素。
- 没有足够数据时不显示空的“值得关注”卡，也不占用固定空间；可以在分析页说明样本不足。

推荐文案层级：

```text
值得关注
22:00 后消费 ¥xxx，较上月同期 +xx%
点击查看消费时间分布
```

在较窄屏幕或大字体下，第三行可以省略，只保留标题和核心事实，避免把首页重新撑高。

### 关闭按钮的行为

可以提供小 `×`，但它必须是“关闭本条洞察”，而不是每次 Widget 重建后暂时消失：

- 关闭后在当前洞察周期内不再出现在首页。
- 关闭状态需要按洞察指纹或周期保存，例如洞察类型、账期、金额区间和比较结果发生变化时视为新洞察。
- 关闭只影响首页展示，不删除分析数据，也不影响分析页查看历史结果。
- 新的账期、新的显著变化或新的洞察类型出现时，可以再次展示。
- 关闭按钮需要阻止事件继续传递，不能同时触发分析页跳转。

如果暂时没有本地的洞察已读/关闭存储能力，第一版宁可不显示 `×`，也不要做成刷新后又出现的假关闭；可以先只做点击进入分析页。

### 不同严重程度的表现

后续如果“值得关注”扩展为多种消息，建议区分而不是全部使用同一种卡片：

| 类型 | 例子 | 首页表现 |
| --- | --- | --- |
| 洞察 | 深夜消费比例上升 | 绿色/薄荷色轻量洞察条 |
| 预算提醒 | 本月预算使用超过 80% | 使用 warning 色，提供预算详情入口 |
| 系统消息 | 数据导出完成、同步失败 | 使用消息中心或一次性提示，不混入消费洞察 |

首页仍只展示最高优先级的一条；多条内容应进入独立的“值得关注”列表或消息抽屉，避免首页堆叠多个横幅。

### 推荐结论

“值得关注”不建议直接改成公告卡，也不建议做成短暂 Snackbar。推荐使用可关闭的轻量洞察条：默认显示一条、整条点击跳转、右上角小 `×` 只关闭当前洞察，并按账期或内容变化重新生成。这样既保留功能价值，又不会和首页的预算、目标主任务争夺空间。
