现在进入第二阶段：

把当前以 Mock 数据为主的 App，
升级为真正可以长期使用的本地记账 App。

本阶段核心目标：

“所有账单、账户、分类、目标数据都真正存入本地数据库，
关闭 App、重新启动以后数据仍然存在。”

技术栈：

Flutter
Riverpod
Drift
SQLite

不要开发云同步。
不要开发登录。
不要接后端。

==================================================
一、首先检查当前代码
==================================================

先完整检查：

lib/
pubspec.yaml
已有 Model
已有 Repository
已有 Mock 数据
已有页面
已有公共组件

不要直接重写。

需要尽量保留当前已经完成的 UI 和设计系统。

执行前先告诉我：

1. 当前数据架构是什么
2. 哪些 Mock 数据需要替换
3. 准备新增哪些数据库表
4. 准备修改哪些文件
5. 是否存在需要迁移的 Model

然后再执行。

==================================================
七、替换 Mock 数据
==================================================

首页
流水页
目标页

现在全部从真实 Repository 获取数据。

但为了第一次运行体验：

默认账户

演示目标可选

注意：

不要每次启动重复插入。

需要 seed/version 机制。

==================================================
八、删除逻辑
==================================================

重要：

账单删除默认使用软删除：

deletedAt

不要直接物理删除。

因为后续：

云同步
多设备
恢复
冲突处理

都需要 deletedAt。

==================================================
九、数据库版本
==================================================

从第一版开始建立：

migration

不要以后修改字段直接删库。
