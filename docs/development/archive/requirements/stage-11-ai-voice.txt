现在开发 AI 语音记账。

原则：

ASR负责语音转文字。

规则/AI负责：

文字 → 结构化账单。

不要把整个音频直接交给大语言模型处理财务逻辑。

==================================================
流程
==================================================

用户长按 +

↓
录音

↓
Speech To Text

↓
文本

例如：

昨晚十一点跟朋友唱歌680，
打车回家38，
都是微信。

↓
解析

↓
生成：

两笔交易。

==================================================
设备端优先
==================================================

如果系统能力允许：

优先设备端语音识别。

不支持或失败：

调用云 ASR。

必须抽象：

SpeechRecognitionService

不要把具体供应商写死在页面。

==================================================
结构化解析
==================================================

建立：

TransactionParser

先尝试：

规则解析。

简单句：

午饭32
滴滴28
工资9800

不用 LLM。

复杂句：

调用 AI。

==================================================
AI输出
==================================================

强制 JSON Schema。

例如：

[
 {
   "type": "expense",
   "amount": 680,
   "category": "娱乐",
   "subcategory": "KTV",
   "occurredAt": "...",
   "account": "微信"
 },
 {
   "type": "expense",
   "amount": 38,
   "category": "交通",
   "subcategory": "打车",
   "occurredAt": "...",
   "account": "微信"
 }
]

==================================================
重要
==================================================

LLM不能：

自己计算余额
修改预算
计算同比
决定资产总额

这些由程序完成。

==================================================
时间解析
==================================================

支持：

今天
昨天
昨晚
前天
晚上11点
上周六

解析成明确 occurredAt。

==================================================
确认页
==================================================

语音解析完成后：

显示结构化结果。

高置信度：

一键确认。

低置信度：

让用户修改。

==================================================
个人学习
==================================================

用户修改分类：

更新 MerchantRule / Personal Classification Memory。
