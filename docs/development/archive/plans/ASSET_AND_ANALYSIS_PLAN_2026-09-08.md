# 资产负债与收支面板追加方案（2026-09-08）

## 用户追加需求

用户明确补充：需要当前财产情况、各渠道现有存款及存款形式、负债情况、收支分析，以及完善消费分析面板并决定展示位置。本方案纳入当前 Luna 开发任务；原审查中的本地资产负债能力不再因原首批范围而全部暂缓。

## 信息架构

保留「首页 / 流水 / 目标 / 我的」四个 Tab。

1. 首页：保留安心可花主卡；增加紧凑的「资产概览」卡，突出净资产，显示总资产、总负债，可点击进入资产总览；增加本月收入、支出、结余摘要，可进入收支分析。不要把完整账户清单和全部图表塞进首页。移除未开放 Pro/Family 推广后有空间容纳真实功能。
2. 独立「资产总览」：按币种计算总资产、总负债、净资产；下面按账户/渠道和资金形式展示余额、占比，提供管理账户及校准余额入口；我的→账户与资产同样能进入。现有账户管理复用，不重造第二套账户数据。
3. `/analysis` 升级为「收支分析」：先展示收入、支出、结余、收支随时间的趋势、收入/支出分类构成；原有日常消费、大额剔除、时间分布、行为洞察保留为下半部分「消费习惯」。从首页收支摘要和流水明确按钮进入。
4. 路由返回应回到来处，使用现有 GoRouter 机制；不为了入口便利新增五/六个一级 Tab。

## 数据与口径

### 账户渠道与资金形式

- 账户仍是余额事实来源，例如「招商银行工资卡」「微信」「支付宝」「现金」「信用卡」。渠道继续利用现有 AccountType + name，无需臆造银行接口。
- 资金形式与渠道是不同维度。为资产账户补可选形式，例如未注明、现金、支付账户余额、活期存款、定期存款、投资理财、其他资产；以真实可编辑字段持久化，而不是根据名称猜测「定期」。信用卡/负债账户以负债身份显示，不强行列为存款。
- 旧数据新增字段默认「未注明」，不把全部银行卡历史余额自动变成活期存款。UI 可给新账户合理默认值，但必须展示供用户修改。
- 余额来自手动账本，页内说明「按账本记录计算，可校准为实际余额」；不能宣称已同步银行或钱包。
- 没有汇率系统，按币种分组，不能把 CNY/USD 等直接相加。首页可优先显示 CNY 并在存在外币时提示另有其他币种；资产总览必须可查看它们。
- 归档是隐藏/停用，不会清零。非零归档账户不得静默从财产合计消失；总览应包含并标识或清楚分列，提供查看与恢复入口。

### 有符号余额与负债

- 复用现有流水资金方向：支出减、收入加、转账一减一加，内部余额采用有符号金额。负数表示欠款/账面负余额，正数表示持有资金或溢缴款。
- 同一币种「账面总资产」汇总正余额，「账面总负债」汇总负余额绝对值，「净资产」为两者之差。对非负债账户出现负余额须显式提示核对初始余额/余额校准，避免将缺少初始化的现金或钱包负数当成已确认现实欠款。
- 信用卡/负债新建和校准表单提供明确的「欠款金额 / 溢缴或预存」语义。欠款用户填正数，写入内部负值；已有正余额显示为正余额/溢缴款并提供校准，不自动翻转历史数据。
- 信用卡还款在本地可通过现有双账户转账完成，提供操作指引或入口，不能再记录一次消费造成双算。

### 余额校准

- 对已存在账户补「校准余额」，用户输入当前实际余额/欠款；解释将生成一条余额调整记录，不计入收入或支出。
- 在同一个数据库事务中读取最新余额、计算整数分差额、写 adjustment 记录并调整账户余额。相同金额不写无意义记录；重复点击不能重复修正。
- 当前 TransactionType.adjustment 已存在，优先扩展其正/负差额校验与展示，不创建平行账务模型。其他交易仍要求正数；adjustment 不计入预算/收入/支出/消费趋势。
- 调整流水要显示「余额校准」及正确资金方向，不能通过仅支持支出/收入/转账的快速编辑表单误改成消费。若允许删除，复用余额回滚与确认语义。
- 归档恢复需要 Repository/DAO/UI 都接通，恢复不改变余额，也不重复应用历史流水。

## 收支分析的最低完整面板

- 复用选定 AnalysisPeriod 与修正后的日期区间，一致过滤软删除和未来记录。
- 本期总收入、总支出、结余及笔数；用真实交易计算，不从账户余额差额倒推（初始资金/校准不是收入）。
- 趋势：7/30 天等显示按日收入/支出（可用已有 Flutter 绘制能力，不引入大型图表库）；本月/上月可按日，长周期适度聚合；空数据有明确空态，金额可读，不制造走势。
- 收入分类、支出分类分开展示金额和占比，用户能看清钱从哪里来、花到哪里；转账/余额校准不计经营收支。退款/借贷等扩展枚举的经济语义暂沿用现状并在记录中保留具体类型，后续专项统一，不能宣称已完成借贷模块。
- 展示「总支出」与「日常消费（剔除重大一次性）」的区别；原消费行为卡下移，避免以深夜消费替代全面收支。
- 上期为零时不显示伪造增长率；本月与上月可比日区间明确写出。无数据、数据加载中、读取失败必须可区分。
- 小屏/大字体采用可换行摘要、横向滚动图表或标签，不靠缩小所有字体掩盖问题。首屏提供结论，进一步分析通过下方内容展开。

## 实施与验收约束

- 由现有一个 GPT-5.6 Luna 子代理分片实施，优先复用现有 AccountRepository/TransactionRepository/AnalysisRepository、AppCard、MoneyText 与主题。先完成手中切片，再补模型/迁移和资产链路，最后联动首页与分析 UI。
- 新增 Drift 字段需要 schemaVersion 增量迁移、重新生成代码及旧版保留余额测试。不要手工改生成文件，不通过删库/重装规避迁移。
- 至少测试：旧账户迁移保持金额；新欠款账户支出后欠款增加、还款转账后欠款减少；正负校准与无变化；校准不影响收支/预算；归档/恢复不改合计；币种不混加；收入支出趋势/分类与总额一致；首页跳转/返回；空/错/窄屏布局。
- Android 模拟器 UI 验收真实资产入口与收支面板；保留用户已有数据，构建后使用覆盖安装。实机银行同步/投资行情没有实现，不得声明已联通。
