# Windows Android 开发工具

双击项目根目录的 [记账工具.bat](../../记账工具.bat)，输入菜单编号即可构建、安装和截图。输入 `0` 返回或退出。

脚本使用 Windows 自带的 Windows PowerShell 5.1，菜单和安装逻辑嵌入 BAT，版本递增共用项目的 `scripts/bump_build_version.dart`，复用 Flutter 自带的 Dart，无需额外安装脚本运行环境。菜单和提示为中文；Flutter、Gradle、ADB 的原始日志保留原文。

## 编译安装包

1. 选择调试版、性能分析版或发布模式版。
2. 选择全部功能开放或正常会员限制，分别传入 `ALL_FEATURES_FREE_FOR_TESTING=true/false`。
3. 选择按架构拆分或通用安装包。
4. 选择只保存，或编译后安装并启动。
5. 自动将 `pubspec.yaml` 的末位版本号和构建号加 1；无需输入版本。从 `1.0.1` 开始，下一次为 `1.0.2`。编译失败也保留已分配版本，安装已有包不递增。

新包归档到项目 `dist/`，文件名包含版本、构建模式、功能权限、时间和架构。例如：

```text
jizhang_app-1.0.0+4013-debug-open-20261004-012700-000-universal.apk
```

`open` 表示测试时开放全部功能，`membership` 表示正常会员限制。发布模式沿用项目签名策略；目前没有 `android/key.properties`，使用调试签名供本地验收。选择正常会员限制不会自动补齐生产服务或支付配置。

## 安装已有版本

从项目 `dist/`、项目上一级 `dist/`、`build/app/outputs/flutter-apk/` 汇总 APK，按修改时间从新到旧列出文件名、大小和目录。多设备连接时可以选择真机或模拟器；未授权和离线设备不可选。

安装使用 `adb install -r` 保留应用数据，成功后启动项目 `MainActivity`。通过文件名识别拆分包架构，并与设备支持的架构核对。架构冲突、签名冲突和版本降级都会提示原因，不自动卸载或清空数据。

旧包最高已知构建号为 `6020`；2026-10-06 起从 `6021` 继续递增。Gradle 配置统一拆分包和通用包的构建号，切换包类型时也可以持续升级。

## 截图和日志

选择“设备截图并打开”，截图将保存到 `dist/windows-tool/screenshots/`，以时间命名并通过系统默认程序打开。截图先保存到设备临时文件，再通过 `adb pull` 传输，避免 PowerShell 二进制重定向损坏图片；完成或传输失败后清理设备临时文件。

每次构建、安装、截图或检查环境的命令输出和退出码保存到 `dist/windows-tool/logs/`。主菜单提供安装包、截图和日志目录入口。

## 环境检查

默认复用项目旁的 `tools/flutter_sdk/flutter`、`tools/android-sdk` 和 `tools/jdk21`，环境调整仅作用于当前工具进程。也支持通过 `FLUTTER_BIN`、`ADB_BIN` 指定工具文件，或从系统 `PATH` 查找。脚本应与 `pubspec.yaml` 放在同一目录，支持从其他工作目录启动。

手机需连接电脑、开启 USB 调试并允许授权。工具检查会显示项目版本、包名、工具路径、签名状态和 ADB 设备列表。
