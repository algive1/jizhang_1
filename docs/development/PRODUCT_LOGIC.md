# 好好记账：账本、自动记账与 AI 记账产品逻辑

更新时间：2026-09-09

## 产品定位

核心原则是「先记录，再确认；自动化可以提效，但不能悄悄改账」。所有自动产生的流水都必须带来源和原始事件标识，系统只做幂等去重，不自动删除用户已有流水。

本版本优先完成离线个人账本闭环，并补齐家庭/企业账本的本地真实共享联调；公网部署、支付验签、会员权益服务、短信和云端大模型仍属于后续服务端接入范围，客户端没有用假数据代替。

## 1. 账本选择器

### 用户流程

1. 首页顶部展示「我的账本」和当前账本名，点击账本名或箭头从顶部安全区打开书架抽屉。
2. 每本账本显示真实书本层次：书脊、封面内框、高光、投影、类型和本地/共享状态；当前账本有边框和勾选标识。点击列表项完成切换并关闭抽屉，切换加载期间不显示旧账本金额。
3. 长按账本打开操作菜单：重命名、删除。删除必须二次确认；默认「个人账本」不可删除，至少保留一个账本。
4. 点击「新建账本」输入 1–40 个字符的名称并选择 personal/family/enterprise 类型。创建成功后自动切换到新账本；选择家庭或企业不会静默上传旧数据。
5. 删除采用归档方式，账本从可选列表移除，原始数据不物理抹除，避免误操作导致不可逆数据丢失。

### 会员限制

| 能力 | Free | Pro 月卡 | Family |
| --- | ---: | ---: | ---: |
| 活跃个人账本 | 3 个 | 20 个 | 50 个 |
| 本地手动记账 | 不限 | 不限 | 不限 |
| 账本切换/重命名 | 支持 | 支持 | 支持 |
| 云同步 | 本地离线 | 本地后端联调 | 本地后端联调 |
| 家庭/企业整本共享 | 需明确启用并登录 | 需明确启用并登录 | 需明确启用并登录 |

数量限制必须以服务端权益为最终准入，客户端限制只负责即时反馈；本地版本执行自建活跃账本上限，受邀加入不占自建额度。个人账本不会因登录自动上传。

### 账本隔离规则

- 账户、期初余额、分类、预算、流水、目标、商户记忆、收件箱和支付通知目标都带有 `bookId`。
- 写入流水时，账户、转入账户和分类必须属于同一本账；本轮不支持跨账本直接转账。
- 余额校准和目标贡献记录真实操作者，并写入当前账本；企业首页把月收入减月支出称为“收支结余”。
- 个人账本只保存在本机。家庭/企业账本启用共享前展示上传范围，只有用户明确确认后才上传该账本账务数据。

### 共享与离线

登录后可以创建共享账本、邀请成员、接受邀请、撤销邀请、退出或归档。所有者/管理员可以管理共享数据，普通成员只能修改自己的流水。离线修改先写入本地 outbox，联网后按稳定 `operationId` 提交；同一实体版本冲突会暂停该队列，用户选择采用服务端版本或基于最新版本重新提交。撤销权限后本地草稿保留为待处理内容，不标记为共享成功。

## 1.1 首页年月选择

月账单卡片的年份和月份分别可点击选择，支持前后月份、跨年、闰年二月和回到本月，但禁止未来月份。所选月份只改变顶部收入、支出和收支结余，以及进入流水/分析时继承的 `month=YYYY-MM`；今日安心可花、趋势和下方记录继续使用当前月份口径。切换账本不会覆盖所选月份，应用重启默认回到本月。

## 2. 会员购买自动记账

### 业务链路

```text
用户选择月卡/年卡
  → Apple IAP 或微信支付创建订单
  → 服务端验签并确认 paid
  → 客户端收到 VerifiedMembershipPurchase
  → 记录「好好记账会员」支出
  → 刷新会员权益和账本数量/云同步能力
```

只有支付 SDK 或服务端回调确认 `paid` 后才能写入消费流水；下单中、失败、取消和退款不记为消费。支付账户由购买流程明确传入，不根据支付渠道擅自猜测用户的资金账户。

### 去重规则

- `orderId` 是业务幂等键。
- 流水 ID 由 `orderId` 经过稳定哈希生成，重复回调不会产生第二行。
- 写入 metadata：`autoType=membershipPurchase`、订单号、商品号、支付提供方。
- 发生并发写入时，以数据库已提交的确定性 ID 为准，后到请求返回已有流水。
- 退款不删除原消费；应由后续退款事件生成独立收入/冲正记录，保留原订单关联。

代码已提供 `MembershipPurchaseBookkeepingService` 和幂等测试；当前工程没有真实支付 SDK、服务端订单和回调验签，因此不能声称已经完成实际购买联调。

## 3. Android 支付通知自动记账

### 用户流程

1. 用户在「我的 → 支付通知记账」中查看系统通知授权状态。
2. 未授权时跳转 Android 通知访问设置；用户返回后再开启开关。
3. 开启后，原生监听器只接收微信、支付宝、云闪付的支付相关通知，写入本机待处理队列。
4. App 启动或回到前台时读取队列，解析金额、商户、时间、支付账户，写入当前账本。
5. 解析失败的通知保留在队列，不会被当成成功流水；用户关闭开关后不再处理队列。

### 安全与去重

- 支付通知监听是 Android 专属能力，需要用户显式授权；iOS 和不支持的平台显示不可用。
- 原生层只收集必要字段：应用包名、通知 key、标题、正文、发布时间；队列上限 100 条。
- `notificationKey` 和通知中的订单号均作为幂等依据；重复通知只确认已处理，不重复入账。
- 自动流水标记 `source=auto`，metadata 记录通知 key、订单号和来源包名。
- 系统不因“疑似重复”自动删除任何已有流水；已有的智能收件箱继续负责人工确认。
- 处理成功后删除队列项；无法解析的项保留，便于后续规则升级后重试。

代码已完成 Android `NotificationListenerService`、MethodChannel、通知解析和本地幂等测试。真实设备还需验证微信/支付宝不同版本的通知文案、系统权限页、进程被杀后的队列保留以及隐私合规文案。

## 4. AI 记账

### 交互链路

```text
自然语言输入/语音转文字
  → 本机规则解析金额、类型、分类、时间、账户、商户
  → 复杂或低置信度内容进入 AI gateway（有权益且有额度时）
  → 严格 JSON schema 校验
  → 用户编辑金额/分类/账户/时间
  → 用户点击确认
  → SQLite 事务批量写入并执行分类与去重
```

示例：`今天午餐 35 元，咖啡 18 元，都用微信` 应得到两条待确认记录；缺少账户或分类时必须补全后才能保存。解析页支持逐笔编辑，不能因为 AI 给出了结果就静默写账。

### 解析字段

`type`、`amount`、`currency`、`category`、`subcategory`、`occurredAt`、`account`、`merchant`、`confidence`、`rawFragment`。AI 输出必须是版本化 JSON 数组，类型、金额、日期和必填字段校验失败则回退本机规则结果并提示用户。

### 权限建议

| 能力 | Free | Pro 月卡 | Family |
| --- | --- | --- | --- |
| 手动记账 | 不限 | 不限 | 不限 |
| 本机自然语言/语音规则 | 不限，文本不出设备 | 不限 | 不限 |
| 云端 AI 解析 | 默认关闭或每月 3 次 | 每月 100 次 | 每月 200 次，按家庭额度 |
| 编辑后确认再入账 | 必须 | 必须 | 必须 |
| AI 失败回退本机规则 | 支持 | 支持 | 支持 |

额度必须由服务端原子扣减，不能以客户端计数作为最终权限判断。当前工程已经复用语音确认页实现文字模式和 `AiParsingGateway` 契约，但没有配置真实 LLM endpoint、模型、额度服务或 API key，所以当前可验证的是本机规则解析和确认保存链路，不是云端 AI 联调。

## 统一数据约束

- 流水金额以整数分写入 SQLite；展示层统一按币种格式化。
- 每条流水必须关联 `bookId`、账户、发生时间和来源。
- 自动流水必须有稳定事件标识；重复事件返回原记录而非再次创建。
- 删除账本使用归档，不清理历史交易表；生产云端还需要删除墓碑、权限校验和审计日志。
- 账本数量、云同步、家庭成员和 AI 额度均不能只依赖客户端 UI 隐藏按钮。
